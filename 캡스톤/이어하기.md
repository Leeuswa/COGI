## 1. 내가 요청한 것 (대화 순서대로)

1. COGI 프로젝트를 학교에서 **지금 막 시작한 것**으로 해서 양식 작성. 팀원 4명 그대로
2. **개인별로 적어야 하는 항목, 협정서는 제외.** 결과보고서도 아직 안 씀
3. 결과보고서 대신 **중간보고서를 매주** 작성 → 그 주에 어떤 활동을 했는지
4. hwp 파일로 그대로 만들기. 폴더는 **`E:\캡스톤`**
5. 중간보고서(양식9-1)는 원래 1페이지 → **같은 양식으로 5페이지**
   - 1쪽 : 통합본 (`팀원 역할 : 정상연 : ~ / 이수환 : ~` 식으로 각자 뭐 했는지 요약)
   - 2쪽 : 나(이수환) / 3·4·5쪽 : 다른 팀원 각자
6. **AI가 쓴 티 안 나게, 내 말투 그대로**
7. (정정) 처음에 1주차로 만들었는데 아님 → **오늘(09.30)이 5주차, 12주차까지.** 5주차는 크게 많이 하면 안 되고
   요구사항 정의서·기능 정의서 등 **전체 계획 + 프로젝트 토의**, 개발은 **아주 살짝** 시작한 것처럼
8. **매주 완성된 화면을 실행해서 보여드려야 함.** 전체 화면 다 보이면 안 되고 매주 조금씩 완성한 것처럼
   → COGI 폴더를 복사해서 주차별로 만들기 (그때는 5주차만)
9. **메인페이지도 좀 불안정하게** (덜 다듬어진 상태)
10. **자료수집, 레퍼런스 수집** 문서도 만들기
11. 중간보고서 사진 칸에 **사진 넣기 : 테두리 적당히 두껍게, 글자처럼 취급, 사진 아래 [설명] 대괄호**
12. 이어서 할 수 있게 md로 정리 (이 파일)
13. 전체 양식 파일(`[서식] 2026년 캡스톤디자인 관련 양식.hwp`)도 처음 요청대로 작성 → 과제계획서 완료
14. zip 말고 **파일을 바로** 달라고 함 (다운로드는 파일 단위로)
15. **(아직 안 함)** 5주차 결과물에 **내가 직접 수정한 것들이 있음 → 그거 먼저 확인하고, 그 방식대로 6주차~12주차 만들기**

## 2. 꼭 지킬 규칙

1. **이미 다 만들었다고 쓰면 안 됨.** 계획하고 조금씩 만들어가는 느낌
2. **매주 실행되는 화면을 조금씩 늘려간다.** 한 주에 너무 많이 하지 않기. 미완성 티(TODO, "준비 중", 임시 문구)도 적당히 남김
3. 글 말투 : 짧은 개조식. `~정함`, `~확인함`, `~만들어둠`, `~해봄`, `~하라고 하심`
   - 번역투, "~를 통해", "효율적인", 과한 병렬 나열, 이모지 금지
4. 결과보고서(양식6·7·8), 최종보고서(9-2), 지출내역서(10), 협정서(5-1·5-2), 개인 동의서(4-2)는 작성 안 함
5. 학번·휴대전화·이메일 같은 개인 항목은 비워둠
6. 모든 결과물은 `E:\캡스톤` 안에
7. 커밋 메시지에 Claude 공동작성자 트레일러 넣지 않음 (원본 레포 HANDOFF.md 규칙)

## 7. 보고서 생성 도구 (`_도구\hwp`) — 기술 메모

hwp 5.0 바이너리(OLE + 레코드)를 직접 고쳐서 만든다. 한글 프로그램 없이 생성 가능.

파일
- `양식9-1_원본.hwp` : 중간보고서 양식 / `전체양식_원본.hwp` : 전체 양식
- `hwplib.py` : 레코드 읽기/쓰기, raw deflate 압축/해제
- `content.py` : 중간보고서 내용 (**주차마다 여기만 고침**)
- `build.py` : 중간보고서 생성 (양식 1장을 5장으로 복제 + 글 + 사진)
- `forms_content.py` / `fill_forms.py` : 과제계획서 생성
- `pack.js` : OLE(cfb) 로 hwp 묶기 + BinData(사진) 스트림 추가
- `photos.js` : 화면 캡처 + 테두리 (클라우드용이라 폰트 우회·경로는 PC에 맞게 고쳐야 함)
- `shots.js`, `render.js` : hwp.js 뷰어로 미리보기 캡처 (`hwp.js`, `esbuild` 로 bundle.js 만들어야 함)
- `make.bat` : 중간보고서 한 번에 생성

양식9-1 구조 메모 (build.py 가 쓰는 레코드 인덱스, 원본 기준)
- 본문은 문단 하나에 표 2개(제목표, 본표). 본표 = 레코드 36~253
- 팀명 칸 113 / 팀장명 122 / 과제명 131 / 지도일시 필드 155·156 / 내용 칸 LIST_HEADER 171(문단 172~198 을 통째로 교체) / 사진 칸 204·208 / 하단 날짜 220·221
- 내용 칸 문단모양 42 → DocInfo 에서 줄간격 160% → 130% 로 바꿈 (한 쪽에 들어가게)
- 페이지 복제 : `[양식9-1]` 문단(쪽 나눔) + 본표 문단 복사. 마지막 문단만 last 플래그
- 사진 : 원본의 '산학협력처장 귀하' 그림 문단(247~253, 글자처럼 취급)을 틀로 복사 → 크기·BinData ID 바꿈
  - SHAPE_COMPONENT 배율 행렬은 1.0 으로, 원래 크기 = 현재 크기
  - BinData 는 DocInfo BIN_DATA(속성 0x0001=문서 압축 따름) + 스트림 `BinData/BIN000N.png` 는 raw deflate 로 저장
  - ID_MAPPINGS 첫 값(BinData 개수) 증가
- 편집은 **뒤쪽 인덱스부터** 해야 앞 인덱스가 안 밀림 (이거 틀려서 날짜가 사진 레코드 자리에 들어간 적 있음)

표 칸 채우기 메모 (fill_forms.py)
- 칸 안 문단 헤더는 LIST_HEADER 와 **같은 레벨**. 칸 범위 = 다음 LIST_HEADER(같은 레벨) 또는 더 바깥 레코드 전까지 (이거 틀려서 글이 라벨 위로 들어간 적 있음)
- 빈 칸은 문단 교체, 라벨 있는 칸(양식3 "⓵ 팀 소개 :" 등)은 뒤에 문단 추가 + LIST_HEADER 문단 수 갱신
- `%fmu`(계산식) 필드는 안의 숫자만 바꿈

cfb 라이브러리 주의
- cfb.js 가 저장할 때 `\u0001Sh33tJ5` 라는 쓸데없는 스트림을 끼워넣음 → `pack.js` 가 처음 실행 때 cfb.js 를 패치해서 막음

hwp.js 뷰어 주의 (확인용일 뿐)
- BinData 가 압축 안 된 jpg 면 터짐 → 번들 만들 때 inflate 를 try/catch 로 패치했음
- 쪽 넘침은 제대로 안 보여줌. 양식3 "과제수행 계획서" 제목이 맨 아래 찍히는 건 원본도 똑같음 (한글에선 정상)
